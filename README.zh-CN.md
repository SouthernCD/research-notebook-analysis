# Research Notebook Analysis

[English](README.md)

## 我们理想的工作方式

我们希望搭建一套基于 VS Code 和 AI agent 的协同科研工作流，让研究者能够一步步把握研究思路与分析过程，在观察、讨论和尝试中不断前进。

研究者始终坐在驾驶位：决定要问什么、关注什么证据、如何理解结果，以及下一步往哪里走。AI agent 是辅助驾驶，帮助整理问题、准备代码、解释方法、排查错误，并把研究者指向的具体任务落实到项目中。你可以随时追问、调整方向，也可以要求先解释再修改。

随着探索推进，项目逐渐形成一组能反映整个研究进展的笔记本。笔记本串起完整分析流程，呈现关键技术选择、实际结果及其核心解释，并记录或明确引用复现所需的数据来源、环境、参数、代码和步骤。未来回看时，读者能够理解为什么这样做、结果支持什么，以及如何重新得到这些结果。

## 笔记本如何承载研究

每本笔记围绕一个明确的科学阶段展开，几本笔记按分析依赖衔接。重要参数和调用在使用处可见；复杂方法说明必要定义，简单操作只需简短提示；图表之后有帮助读者理解结果的图注。较长实现可以放到 `src/`，完整独立工具可以放到 `tools/`，笔记仍保留它们在研究流程中的入口。

研究记录需要随着真实进展更新：已观察到的结果、据此作出的判断、会影响解释的局限，以及尚待回答的问题，都应在相关位置说清楚。提出的设想与已有证据要能区分。计算与绘图分开，较重步骤保存结果，让下一轮探索可以从已完成的工作继续。

开发和调试期间，英文与中文说明放在同一本笔记中相邻的 Markdown cells，共用一套代码，方便对照和修改。最终发表整理时，可以再选择生成两个语言目录，供不同读者阅读。

## 从一个具体问题开始

你不需要先准备完整研究计划。可以在请求中点名 `research-notebook-analysis`，说明当前的问题、已有材料，以及最希望推进的一步。例如：

> 使用 research-notebook-analysis。我有一份基因型数据和样本环境信息，想研究环境适应，但还没有完整方案。先帮我梳理已有材料，确定第一步值得做什么。

也可以直接提出已有项目中的任务：

> 看看这本笔记，解释它的研究逻辑、关键假设，以及下一步还缺什么证据。先讨论，不修改代码。

> 给这一节增加一项比较。先沿用现有样本和过滤标准，把方法与参数写清楚，准备好代码后告诉我如何运行。

> 调整这张图的布局和图注，沿用已经保存的统计结果。

> 这一步报错了。这是相关笔记路径和错误输出，请结合上下文定位原因。

文件位置、数据格式、相关章节、现有输出，以及希望改变或保留的内容，通常比一份很长的任务说明更有帮助。开始时提供数据说明或小样例即可，大型数据通常留在远端。

## 怎样和 agent 一起推进

一次先推进一个有意义的步骤。Agent 查看现有材料，说明理解与待定选择，准备笔记和代码；你运行、查看结果，再根据观察继续讨论。遇到不清楚的方法，可以要求解释其假设和适用范围；遇到不确定的结果，可以先要求诊断或设计比较，再决定是否扩展分析。

你负责研究目标、科学选择和结果判断；agent 帮助把这些选择表达成可读、可操作、可复现的分析。默认由 agent 准备修改、由你运行并检查。若希望 agent 执行整本笔记，请明确指出笔记和执行要求；启动 Jupyter、安装软件等操作也需要明确提出。运行环境与资源约定通过配套的 `remote-hpc-operator` 管理。

每次修改后，agent 应交代改了哪里、是否需要同步、接下来运行哪些 cells，以及检查什么输出。反馈时尽量带上实际结果、错误或具体疑问。例如：“这个分布和预期不同，先检查样本对齐和分母定义。”这些反馈会成为下一轮工作的起点。

## 本地编辑，远端计算

这套工作方式主要面向本地 VS Code 中保留笔记、远端 HPC kernel 执行计算的项目。源码与配置通过手动 VS Code 任务同步，图表和文字通过 Jupyter 返回显示，大型输入与结果通常保存在远端。项目配置完成后，项目内的私有 Jupyter 启动指南帮助你自行连接和继续工作。

笔记记录分析过程，并引用环境说明、数据清单和源码等复现材料；项目 README 说明笔记顺序与复现起点。Git 保存代码和研究文档的演进，数据与结果则需要在其实际存储位置妥善保留。这样，研究的上下文能够随项目保存下来，后续协作可以从已有记录继续。
